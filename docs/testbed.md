# Стенд эмуляции сети

Стенд воспроизводит плохую сеть между клиентом и сервером на одной Linux-машине: три network namespace, соединённые парами veth, и `tc netem` на маршрутизаторе. Код — в [`testbed/netns`](../testbed/netns), профили сети — в [`testbed/scenarios/profiles.yaml`](../testbed/scenarios/profiles.yaml).

## Топология

```text
   client                      router                      server
  ┌──────────────┐        ┌──────────────────────┐        ┌──────────────┐
  │ eth0         │────────│ toclient    toserver │────────│ eth0         │
  │ 10.0.1.2     │        │ 10.0.1.1    10.0.2.1 │        │ 10.0.2.2     │
  └──────────────┘        └──────────────────────┘        └──────────────┘
                  клиент → сервер: выход через toserver
                  сервер → клиент: выход через toclient
```

Воздействия стоят только на двух интерфейсах маршрутизатора, по одному на направление (NET-1, NET-3). Если поставить netem на интерфейс самого клиента или сервера, отброшенный в локальной очереди пакет увидит TCP-стек отправителя и среагирует как на перегрузку у себя, а QUIC такого сигнала не получит.

## Запуск

Root не нужен:

```sh
make testbed-shell PROFILE=interregion            # шелл внутри стенда
go run ./testbed/cmd/testbed run -profile congested -- ./bench.sh
go run ./testbed/cmd/testbed profiles             # список профилей
go run ./testbed/cmd/testbed show degraded        # команды tc профиля, без запуска
```

Внутри стенда программы запускаются в нужном namespace через `ip netns exec client …` и `ip netns exec server …`, а профиль меняется командой `testbed apply ИМЯ`. Сервер доступен клиенту по адресу `10.0.2.2`.

Как это работает: `testbed` перезапускает себя в новых user-, mount- и network-namespace. В них процесс — root и может создавать namespace, veth и qdisc, а у хоста ничего не меняется. Список namespace для `ip netns` лежит в собственном tmpfs поверх `/run/netns`. Стенд живёт, пока работает команда, и исчезает вместе с ней, даже после падения, поэтому следов не остаётся и повторный запуск всегда начинается с чистого места. Из соседнего терминала `ip netns` стенд не видит.

Нужны `ip` (iproute2), `tc`, `ethtool`, `sysctl` и разрешённые непривилегированные user namespace. Ubuntu 24.04 по умолчанию их запрещает:

```sh
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0   # до перезагрузки
echo 'kernel.apparmor_restrict_unprivileged_userns = 0' | sudo tee /etc/sysctl.d/60-userns.conf   # насовсем
```

## Профили

Значения профиля относятся к каждому направлению, кроме RTT: он делится пополам между направлениями. Так, при `loss: 1%` теряется 1% пакетов в каждую сторону, и пара запрос-ответ теряет примерно 2%.

| Поле | Смысл |
| --- | --- |
| `rtt` | время в пути туда и обратно; по `rtt/2` в каждом направлении |
| `jitter` | стандартное отклонение задержки в одну сторону, нормальное распределение; порядок пакетов сохраняется |
| `loss` | доля потерянных пакетов |
| `loss_burst` | средняя длина пачки потерь в пакетах; без поля потери независимы |
| `reorder` | доля пакетов, которые обгоняют отправленные до них |
| `rate` | полоса узкого места, например `100Mbit`; без поля полоса не ограничена |
| `queue_bdp` | очередь узкого места в BDP, то есть в `rate × rtt` |

Значения профилей пока предварительные и уточняются после пилота (фаза 2). Профиль `none` — без воздействий.

## Как устроены воздействия

На каждом из двух интерфейсов маршрутизатора стоит два qdisc:

```text
root 1: netem   задержка, джиттер, потери, перестановки; очередь 100 000 пакетов
  └─ 10: tbf    полоса и очередь узкого места, если в профиле есть rate
```

- **Задержка и джиттер.** netem задерживает каждый пакет на `rtt/2` плюс случайную добавку с нормальным распределением и стандартным отклонением `jitter`. При случайной задержке netem сам переставляет пакеты: поздний пакет обгоняет ранний, если тому выпала задержка больше. Чтобы джиттер не смешивался с перестановками (NET-2), вместе с джиттером netem получает `rate 100gbit`. С этим параметром он не отправит пакет раньше, чем пакет перед ним, а сама полоса так велика, что ничего не ограничивает.
- **Перестановки.** `reorder X%` отправляет X% пакетов без задержки, и они обгоняют пакеты, отправленные за предыдущие `rtt/2`.
- **Потери пачками.** Используется модель Гилберта (`loss gemodel p r`): в «плохом» состоянии теряется каждый пакет, в «хорошем» — ни один. Пачка длится в среднем `1/r` пакетов, а доля времени в плохом состоянии `p/(p+r)` равна доле потерь. Отсюда `r = 1/loss_burst`, `p = loss·r/(1−loss)`. Например, 2% пачками по 4 пакета дают `p ≈ 0,51%`, `r = 25%`.
- **Полоса и очередь** — у tbf, а не у netem. Лимит очереди netem считает все пакеты, которые ждут своей задержки. На «Межрегионе» (100 Мбит/с, 75 мс в одну сторону) таких около 625 пакетов по 1500 байт, и очередь из `limit` у netem вышла бы вдвое меньше заданной, причём её размер менялся бы с RTT и размером пакетов. tbf стоит после netem, поэтому в его очередь попадают только пакеты, у которых задержка уже прошла. Его очередь задана в байтах и равна `queue_bdp × rate × rtt`, а корзина токенов — одна миллисекунда на полосе узкого места, но не меньше двух полных кадров.

Профиль меняется так: старые qdisc удаляются и ставятся новые. Пока идёт замена, пакеты проходят без воздействий, поэтому профиль меняют между прогонами.

## Подготовка интерфейсов

- **TSO, GSO и GRO выключены** на всех veth. С ними veth передаёт склеенные пакеты до 64 КБ, и netem теряет или задерживает такой пакет целиком, как один.
- **Соседи заданы статически.** Иначе ARP-запросы тоже шли бы через воздействия, и первые пакеты ждали бы ответа на ARP.
- **IPv6 выключен**, чтобы после поднятия интерфейса не было проверки адреса и лишних пакетов.
- **`ip_forward` задан явно** в каждом namespace: 1 на маршрутизаторе, 0 на клиенте и сервере. Новый namespace наследует IPv4-настройки хоста (`net.core.devconf_inherit_init_net`), и без явного значения стенд зависел бы от машины.
- MTU — 1500, как у Ethernet.

## Проверки

- Юнит-тесты сверяют команды, которые строят стенд и применяют профиль, без сети.
- Интеграционные тесты поднимают настоящий стенд. Они проверяют, что пакеты идут через маршрутизатор, медианный RTT по `ping` попадает в 10% от профиля, offload выключен, соседи статические, смена профиля заменяет qdisc, а ядро принимает каждый профиль из `profiles.yaml`. В CI эти тесты обязательны (`QRPC_TESTBED_REQUIRED=1`); на машине без user namespace они пропускаются.
